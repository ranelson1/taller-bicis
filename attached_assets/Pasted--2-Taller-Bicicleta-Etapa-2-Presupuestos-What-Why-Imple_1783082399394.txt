#2 - Taller Bicicleta — Etapa 2: Presupuestos

What & Why

Implementar el módulo de presupuestos, que es el primer flujo operativo real de la app.

El taller normalmente recibe un contacto por WhatsApp, llamada, Instagram o presencial. Desde ahí se crea un presupuesto preliminar con los requerimientos del cliente. El presupuesto puede incluir servicios técnicos, repuestos, mano de obra adicional, diagnósticos, recomendaciones, descuentos u otros ítems.

El objetivo de esta etapa es poder crear, editar, enviar manualmente, versionar, aprobar/rechazar ítems y dejar un presupuesto listo para convertirse en orden de trabajo en una etapa posterior.

Importante:
Usar siempre el término “presupuesto”, no “cotización”.

Done looks like

- Puedo crear un presupuesto desde un contacto inicial del cliente.
- Puedo seleccionar cliente existente o crear uno rápidamente si no existe.
- Puedo asociar una bicicleta existente del cliente o dejarla pendiente si aún no está registrada.
- Puedo registrar canal de origen: WhatsApp, llamada, Instagram, presencial u otro.
- Puedo registrar el requerimiento inicial del cliente.
- Puedo agregar ítems al presupuesto.
- Puedo agregar servicios técnicos desde el catálogo existente.
- Al agregar un servicio técnico, se copia automáticamente:
  - nombre/descripción
  - precio base
  - horas hombre estimadas
  - categoría
  - referencia al servicio original
- Puedo agregar repuestos desde el catálogo existente.
- Al agregar un repuesto, se copia:
  - nombre/descripción
  - precio sugerido
  - referencia al repuesto original
- Puedo agregar ítems manuales: mano de obra adicional, diagnóstico, recomendación, descuento u otro.
- Cada ítem tiene cantidad, precio unitario, total calculado, horas estimadas si aplica, origen y estado de aprobación.
- El presupuesto calcula automáticamente:
  - subtotal
  - descuentos
  - total
  - total de horas hombre estimadas
- Puedo guardar el presupuesto como borrador.
- Puedo marcarlo como enviado al cliente.
- Puedo aprobarlo total o parcialmente.
- Puedo rechazarlo.
- Puedo aprobar/rechazar ítems individualmente.
- Puedo crear una nueva versión cuando el presupuesto cambia después de haber sido enviado.
- Puedo ver historial de versiones del presupuesto.
- Puedo ver un resumen del presupuesto listo para copiar y enviar manualmente por WhatsApp/email, sin integración real.
- En mobile, la lista de presupuestos se muestra como tarjetas.
- En desktop, la lista se muestra como tabla.
- La pantalla de detalle de presupuesto es usable en celular.
- El dashboard empieza a mostrar conteos simples de presupuestos:
  - presupuestos borrador
  - presupuestos enviados
  - presupuestos aprobados
  - presupuestos pendientes de aprobación

Reglas de negocio

1. El número de presupuesto debe ser automático:
   P-0001, P-0002, P-0003, etc.

2. Un presupuesto puede existir sin bicicleta asociada, porque a veces nace desde WhatsApp antes de recibir la bici.

3. Un presupuesto siempre debe tener cliente.

4. El total debe recalcularse automáticamente cada vez que cambian los ítems.

5. Las horas hombre estimadas deben calcularse como la suma de horas de los ítems activos.

6. Los descuentos deben manejarse como ítems de tipo discount con monto negativo o como discount_total, elegir la implementación más simple y consistente.

7. Si un presupuesto está en borrador, se puede editar sin crear nueva versión.

8. Cuando un presupuesto pasa a “Enviado al cliente”, crear una versión snapshot en quote_versions.

9. Si un presupuesto ya fue enviado y luego se edita, marcar estado como “Actualizado después de envío” y crear nueva versión al volver a enviarlo.

10. Si todos los ítems activos están aprobados, el presupuesto puede pasar a “Aprobado”.

11. Si algunos ítems están aprobados y otros pendientes/rechazados, el presupuesto puede pasar a “Aprobado parcialmente”.

12. Si todos los ítems están rechazados, puede pasar a “Rechazado”.

13. Un presupuesto aprobado o aprobado parcialmente debe poder quedar como “Listo para orden de trabajo”, pero no crear todavía la OT real.

14. Cada cambio relevante debe crear un evento en timeline_events:
   - presupuesto creado
   - presupuesto editado
   - presupuesto enviado
   - nueva versión creada
   - ítem aprobado
   - ítem rechazado
   - presupuesto aprobado
   - presupuesto aprobado parcialmente
   - presupuesto rechazado
   - presupuesto listo para OT

Validaciones

- Cliente obligatorio.
- Canal de origen obligatorio.
- No permitir aprobar presupuesto sin ítems activos.
- No permitir marcar listo para OT si no hay al menos un ítem aprobado.
- Cantidad debe ser mayor que 0, excepto descuentos si se implementan como monto negativo.
- Precio unitario debe permitir 0 o más, excepto descuentos si se implementan como negativo.
- Horas estimadas debe permitir 0 o más.
- Si se elimina/desactiva un ítem, recalcular totales.
