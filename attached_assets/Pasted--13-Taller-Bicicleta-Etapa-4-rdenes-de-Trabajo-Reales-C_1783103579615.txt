#13 - Taller Bicicleta — Etapa 4: Órdenes de Trabajo Reales + Checklist Operativo

## Contexto

Ya están implementadas:

- Etapa 0: setup, layout, login, navegación, base de datos y seed.
- Etapa 1: CRUDs maestros de usuarios/mecánicos, clientes, bicicletas, servicios, checklist, repuestos, categorías y métodos de pago.
- Etapa 2: presupuestos completos con ítems, versiones, timeline, aprobación/rechazo de ítems y estado “Listo para orden de trabajo”.
- Etapa 3: recepciones e inspección visual, hallazgos, adicionales desde inspección y vínculo con presupuestos.

Ahora necesitamos implementar la Etapa 4: órdenes de trabajo reales.

Esta etapa es el núcleo operativo del taller. Una orden de trabajo debe nacer desde un presupuesto aprobado o aprobado parcialmente, idealmente con bicicleta recibida. La OT debe copiar los ítems aprobados, asignar mecánico responsable, generar checklist operativo por servicio y permitir actualizar el progreso del trabajo.

IMPORTANTE:
No implementar todavía agenda/calendario, pagos ni facturación. Eso viene en etapas posteriores.

## Objetivo

Implementar el módulo completo de órdenes de trabajo para que el taller pueda:

- Crear una OT real desde un presupuesto aprobado o aprobado parcialmente.
- Asociar la OT a cliente, bicicleta, presupuesto y recepción.
- Copiar solo los ítems aprobados del presupuesto.
- Copiar servicios, repuestos y mano de obra aprobada.
- Generar checklist operativo desde los servicios aprobados.
- Asignar mecánico responsable.
- Cambiar estados de la OT.
- Actualizar avance de checklist.
- Registrar notas internas y notas visibles para cliente.
- Ver timeline de la OT.
- Llevar control de calidad.
- Marcar la OT como lista para retiro.
- Mantener el botón de pagos/facturación fuera de alcance por ahora.

## Alcance incluido

### 1. Crear órdenes de trabajo

La OT debe poder crearse desde:

- Detalle de presupuesto `/presupuestos/:id`
- Detalle de recepción `/recepciones/:id`, si tiene presupuesto asociado aprobado o parcialmente aprobado

El botón “Convertir en OT” ya existía como placeholder. Ahora debe crear una OT real.

Reglas para crear OT:

1. El presupuesto debe estar en uno de estos estados:
   - approved
   - partially_approved
   - ready_for_work_order

2. Debe existir al menos un ítem aprobado en el presupuesto.

3. La OT debe copiar solo ítems activos y aprobados.

4. Si hay ítems pendientes o rechazados, no copiarlos a la OT, pero mostrar advertencia:
   “Este presupuesto tiene ítems no aprobados que no serán incluidos en la OT.”

5. La OT debe asociar:
   - client_id
   - bicycle_id
   - quote_id
   - reception_id, si existe
   - assigned_mechanic_id
   - status inicial
   - total estimado
   - horas hombre estimadas

6. Si el presupuesto no tiene bicicleta, no permitir crear OT. Mostrar mensaje:
   “Para crear una orden de trabajo debes asociar una bicicleta.”

7. Si el presupuesto tiene recepción asociada, copiarla a la OT.

8. Si no tiene recepción asociada, permitir crear OT igual solo si existe bicicleta, pero mostrar advertencia:
   “Este presupuesto no tiene recepción asociada.”

9. No crear agenda todavía.

10. No registrar pagos todavía.

### 2. Número automático de OT

- OT-0002

### 3. Estados de orden de trabajo

Usar estos estados internos:

- `received` → Bici recibida
- `in_inspection` → En inspección
- `waiting_customer_approval` → Esperando aprobación cliente
- `waiting_parts` → Esperando repuestos
- `ready_to_work` → Lista para trabajar
- `in_progress` → En trabajo
- `quality_control` → En control de calidad
- `ready_for_pickup` → Lista para retiro
- `delivered` → Entregada
- `closed` → Cerrada
- `cancelled` → Cancelada

En esta etapa, implementar cambio manual de estado con validaciones mínimas.

Reglas mínimas:

- Al crear OT, estado sugerido:
  - `ready_to_work` si hay presupuesto aprobado y recepción lista para OT
  - `received` si hay recepción pero aún no está marcada lista
  - `ready_to_work` si no hay recepción pero presupuesto está aprobado

- Para pasar a `in_progress`, debe tener mecánico asignado.

- Para pasar a `quality_control`, debe tener al menos un checklist con pasos completados o permitir confirmación manual si no hay servicios con checklist.

- Para pasar a `ready_for_pickup`, debe pasar antes por `quality_control`.

- `closed` todavía no debe depender de pago, porque pagos vienen en Etapa 6.

### 4. Estado de agenda

Agregar en OT un campo simple, pero no implementar agenda todavía:

- `schedule_status`

Valores:

- `unscheduled` → Sin agendar
- `scheduled` → Agendada
- `rescheduled` → Reagendada
- `late` → Atrasada
- `completed` → Completada

En esta etapa, al crear OT dejar:

- `schedule_status = unscheduled`

No crear calendario ni bloques de agenda todavía.

### 5. Mecánico asignado

La OT debe tener un mecánico responsable.

Campos:

- assigned_mechanic_id

Reglas:

- Puede quedar vacío al crear OT si todavía no se sabe.
- Es obligatorio para pasar a estado `in_progress`.
- El selector debe mostrar usuarios activos con rol mecánico o admin.
- Mostrar horas semanales del mecánico como referencia, pero no calcular capacidad todavía.

### 6. Ítems de OT

Crear tabla `work_order_items`.

Cada ítem debe copiar información desde `quote_items`:

- work_order_id
- item_type
- origin

- total
- estimated_labor_hours
- service_id nullable
- part_id nullable
- assigned_mechanic_id nullable
- status
- active
- created_at
- updated_at

Estados de ítem OT:

- `pending` → Pendiente
- `in_progress` → En proceso
- `completed` → Completado
- `cancelled` → Cancelado

Reglas:

- Al crear OT, todos los ítems quedan `pending`.
- Los ítems de tipo servicio deben generar checklist si tienen servicio asociado con pasos.
- Repuestos no generan checklist.
- Mano de obra adicional puede quedar sin checklist.

### 7. Checklist operativo

Crear checklist real de OT a partir de las plantillas de servicios.

Tabla sugerida:

`work_order_checklist_items`

Campos:

- id
- work_order_id
- work_order_item_id
- service_step_id nullable
- step_order
- description
- status
- mechanic_notes nullable
- completed_by_user_id nullable
- completed_at nullable
- active
- created_at
- updated_at

Estados de checklist:

- `pending` → Pendiente
- `in_progress` → En proceso
- `completed` → Completado
- `not_applicable` → No aplica
- `with_observation` → Con observación

Reglas:

1. Al crear OT, para cada ítem aprobado de tipo servicio:
   - buscar pasos del servicio
   - copiar pasos a `work_order_checklist_items`

2. El checklist copiado debe ser independiente de la plantilla.
   Si después se modifica el servicio maestro, no debe cambiar la OT ya creada.

3. Cada paso debe poder:
   - marcarse pendiente
   - marcarse en proceso
   - marcarse completado
   - marcarse no aplica
   - marcarse con observación
   - guardar nota del mecánico

4. Al completar pasos, registrar `completed_by_user_id` y `completed_at`.

5. Mostrar progreso:
   - pasos completados / pasos totales
   - porcentaje de avance por servicio
   - porcentaje de avance general de la OT
