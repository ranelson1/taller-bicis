#22 - Etapa 5A: Nuevo Trabajo Rápido + Ficha Operativa Simplificada

## Contexto

Después de mostrar el MVP a un taller real, el feedback principal fue:

La app está completa, pero tiene demasiados clicks para procesar una bicicleta. El mecánico no quiere navegar entre Presupuestos, Recepciones y Órdenes para hacer un trabajo diario.

El mecánico actúa como:
- mecánico
- recepcionista
- cotizador
- servicio al cliente
- comprador
- cobrador
- administrador

Por eso la UX debe centrarse en una sola pantalla: la Ficha de Trabajo.

Ya existe la entidad `work_cases` y las pantallas:

- `/trabajos`
- `/trabajos/:id`

Pero todavía falta un flujo rápido para crear un trabajo y operar desde la ficha.

## Objetivo

Crear un flujo rápido de “Nuevo Trabajo” y mejorar `/trabajos/:id` para que sea la pantalla principal operativa.

El usuario debe poder crear una ficha de trabajo sin pasar manualmente por Presupuesto → Recepción → OT.

Internamente se pueden seguir usando quotes, receptions y work_orders, pero la UX debe sentirse como:

Nuevo Trabajo → Ficha TR → operar desde ahí.

Pasos del flujo:

#### Paso 1 — Cliente

Debe permitir:

Campos mínimos para crear cliente:

#### Paso 2 — Bicicleta

Una vez seleccionado el cliente:

Campos mínimos:

- marca
- modelo

- tipo
- color
- número de serie opcional
- notas opcionales

No mandar al usuario a `/bicicletas`.

#### Paso 3 — Servicios, repuestos e ítems iniciales

Permitir agregar:

- servicios desde catálogo
- repuestos desde catálogo
- ítems manuales

Cada ítem debe permitir:

- tipo
- descripción
- cantidad
- precio unitario
- horas estimadas opcionales
- aprobado por defecto

Regla UX:
Los ítems iniciales del “Nuevo Trabajo” deben quedar aprobados por defecto, porque representan lo que el cliente está dejando solicitado o ya conversado.

#### Paso 4 — Comentarios iniciales

Campos:

- comentario del cliente
- comentario del mecánico / recepción
- estado inicial de la bicicleta
- accesorios recibidos

Accesorios recibidos puede reutilizar la lógica existente de recepciones.

#### Paso 5 — Crear ficha

Al confirmar, debe crear una ficha de trabajo completa.

Idealmente usar un endpoint backend nuevo para evitar múltiples llamadas frágiles desde frontend:

POST `/work-cases/quick-create`

Este endpoint debe orquestar:

1. Crear o usar cliente.
2. Crear o usar bicicleta.
3. Crear Work Case TR.
4. Crear Presupuesto P asociado al TR.
5. Crear ítems de presupuesto aprobados.
6. Crear Recepción R asociada al TR.
7. Crear OT asociada al TR con los ítems aprobados.
8. Copiar checklist de servicios, como ya hace la lógica actual de OT.
9. Recalcular estado del TR.
10. Redirigir a `/trabajos/:id`.

Si es demasiado grande crear todo en backend, se puede hacer desde frontend reutilizando endpoints existentes, pero la opción backend es preferible para mantener consistencia.

Resultado esperado:
El mecánico termina el flujo y llega directo a la ficha `TR-XXXX`.
